# VK Photo Exporter

Скачивает фотографии из личных переписок, групповых бесед и диалогов с сообществами
по официальному архиву данных ВКонтакте (`Archive.zip` из «Запросить архив»).
Работает локально, без токена VK и без авторизации.

- открывает `Archive.zip` или уже распакованную папку архива;
- сама находит все переписки (`messages/<peer_id>/messages*.html`), ручной выбор не нужен;
- отбирает фото по **дате сообщения** за заданный период (границы включаются);
- скачивает асинхронно, с повторами, проверкой содержимого и возобновлением после прерывания;
- раскладывает файлы по перепискам и годам, пишет отчёты и базу прогресса.

## Самый простой способ: программа с окном

1. Скачайте `VKPhotoExporter.exe`. Python ставить не нужно.
2. Запустите его двойным кликом. Windows может показать «Windows защитила ваш компьютер»:
   программа не подписана сертификатом. Нажмите «Подробнее» → «Выполнить в любом случае».
3. В окне:
   - **Архив ВКонтакте**: «Выбрать ZIP…» (или «Папка…», если архив уже распакован).
     Если `Archive.zip` лежит рядом с программой, он подставится сам;
   - **Период**: годы «с» и «по», оба включительно;
   - **Куда сохранить**: по умолчанию папка `VK_Photos` рядом с архивом;
   - **Скачать фото**. Прогресс виден в окне. «Стоп» или закрытие окна сохраняют прогресс,
     повторное «Скачать фото» продолжает с того же места.
4. «Открыть папку с фото» откроет результат. Там же лежит `reports/` с отчётами.

«Только анализ» быстро считает, сколько фото найдено за период, ничего не скачивая.
Галочка «Ещё раз проверить фото, которые в прошлый раз были недоступны» перепроверяет
ссылки, которые сервер VK отклонил в прошлый раз. Иногда VK отказывает временно.

### Как собрать exe самому

Нужен установленный Python 3.11+. В папке проекта запустите `build_exe.bat`.
Готовый файл появится в `dist\VKPhotoExporter.exe` (около 19 МБ, один файл без зависимостей).
Без сборки окно можно открыть командой `python gui.py`.

## Установка для командной строки (Windows 11)

1. Установите Python 3.11 или новее: <https://www.python.org/downloads/> (отметьте «Add python.exe to PATH»)
   или в PowerShell: `winget install Python.Python.3.12`.
2. Откройте PowerShell в папке программы и выполните:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Если PowerShell запрещает запуск `Activate.ps1`, выполните один раз
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` или вызывайте Python напрямую:
`.\.venv\Scripts\python.exe main.py ...`.

## Использование

Предварительный анализ без скачивания:

```powershell
python main.py --archive "Archive.zip" --start-date 2014-01-01 --end-date 2016-12-31 --scan-only
```

Скачивание:

```powershell
python main.py --archive "Archive.zip" --output "VK_Photos" `
  --start-date 2014-01-01 --end-date 2016-12-31 --concurrency 5
```

(в PowerShell перенос строки — обратный апостроф `` ` ``, в cmd — `^`, в bash — `\`.)

Пробный запуск на 50 ссылках: добавьте `--limit 50`. Распакованный архив: `--archive "D:\VK\Archive"`.

| Параметр | Назначение |
|---|---|
| `--archive` | `Archive.zip` или папка распакованного архива (обязательный) |
| `--output` | папка результата, по умолчанию `VK_Photos` |
| `--start-date`, `--end-date` | период `ГГГГ-ММ-ДД`, обе границы включаются; без них — вся история |
| `--scan-only` | только статистика; с `--output` дополнительно пишет отчёты |
| `--concurrency` | одновременных загрузок (по умолчанию 5) |
| `--retries` | повторов при временных ошибках (по умолчанию 5) |
| `--soft-retries` | повторов при 404/403, которые CDN VK иногда отдаёт временно (по умолчанию 3) |
| `--timeout` | тайм-аут запроса в секундах (по умолчанию 60) |
| `--retry-failed` | повторить и окончательные ошибки (404/403), а не только временные |
| `--limit N` | обработать не более N ссылок |
| `--no-hardlinks` | копировать вместо жёстких ссылок (см. «Дубликаты») |
| `--no-progress` | без прогресс-баров (для логов) |

### Прерывание и повторный запуск

Можно прервать в любой момент (Ctrl+C или закрыть окно): результат каждой ссылки
сразу пишется в `progress.db`, файлы сохраняются через временный файл и атомарное
переименование, поэтому недокачанных фотографий в папках не бывает. Повторный запуск
той же командой:

- не скачивает заново уже сохранённое;
- повторяет временные ошибки (таймауты, 5xx, 424, 429);
- заново ставит в очередь записи, чьи файлы удалили с диска;
- подхватывает файл, который прерванный запуск успел записать, но не успел внести в базу
  (после проверки сигнатуры и SHA-256);
- не создаёт лишних копий: имена файлов детерминированы, дубликаты определяются по SHA-256.

Два запуска с одной папкой `--output` одновременно работать не могут: папку блокирует
`progress.lock` средствами ОС. Блокировка снимается сама, даже если процесс был убит.

Ответы 404/403 при первом проходе повторяются только `--soft-retries` раз. Чтобы ещё раз
перепроверить все недоступные ссылки (например, через день), запустите ту же команду
с `--retry-failed`.

## Результат

```text
VK_Photos/
├── Personal/<Имя>_<id>/<год>/        личные диалоги
├── Group_Chats/<Название>_<peer_id>/<год>/   беседы (peer_id ≥ 2000000000)
├── Communities/<Название>_<-id>/<год>/       диалоги с сообществами
├── reports/
│   ├── summary.json     сводка: по годам, типам, переписке, причинам ошибок
│   ├── downloaded.csv   скачанные вложения
│   ├── failed.csv       недоступные (с причиной и HTTP-кодом)
│   └── skipped.csv      пропущенные (пересланные сообщения, записи на стене, голосовые, не изображения)
└── progress.db          SQLite: все вложения и их статусы
```

Имя файла: `ГГГГММДД_ЧЧММСС_<id сообщения>_<номер вложения>.<расширение>`, например
`20161231_235959_729064_0.jpg`. Расширение берётся по фактической сигнатуре файла
(jpg/png/gif/webp/…), а не из ссылки. В имени папки всегда есть id, потому что
названия совпадают (в архиве, например, 25 диалогов с удалёнными пользователями «DELETED»).

В CSV по каждому вложению: id и тип переписки, название, id сообщения, номер вложения,
дата, автор и его id (для «Вы» — id владельца архива), тип вложения, исходная ссылка,
фактический URL (для документов), ссылка VK вида `photoX_Y`/`docX_Y`, статус, причина,
HTTP-код, путь к файлу, размер, SHA-256, признак дубликата, число попыток, исходная HTML-страница.
CSV в UTF-8 с BOM, Excel открывает его с кириллицей.

### Дубликаты

Каждый уникальный URL скачивается один раз. Если одно и то же изображение (по SHA-256)
встречается в одной папке «переписка/год» несколько раз, на диске один файл, но каждая
отправка остаётся отдельной записью в базе и в `downloaded.csv` (`is_duplicate=1`).
Если фото есть в разных переписках, оно попадает в папку каждой из них; на NTFS это
жёсткая ссылка, лишнего места она не занимает.

## Как устроен архив (по результатам исследования)

- Страницы в `windows-1251`, по 50 сообщений, от новых к старым.
- Сообщение: `<div class="message" data-id="…">`, заголовок `message__header`:
  `<a href="https://vk.ru/id…">Имя</a>, 21 сен 2016 в 10:46:37`; для своих сообщений — `Вы, …`;
  у отредактированных в конце `(ред.)`. Авторы-сообщества — ссылки `public…`/`club…`.
- Вложение: `attachment__description` (тип) и `attachment__link` (ссылка).
- Тип переписки определяется по `peer_id` папки: `≥ 2000000000` — беседа, `< 0` — сообщество, иначе личный диалог.

Ссылки на фото бывают трёх видов:

| Вид | Пример | Что делаем |
|---|---|---|
| Подписанная ссылка CDN | `sun9-8.userapi.com/impg/…jpg?size=1536x2048&quality=96&sign=…` | качаем как есть |
| Старая прямая ссылка | `sun9-39.userapi.com/c440/u…/x_….jpg` | качаем, при 504/424 повторяем |
| Страница VK | `vk.ru/im?sel=…&z=photo100000001_456239096…` | без входа недоступна, помечаем `requires_auth` |

«Файл» бывает голосовым сообщением (прямая ссылка `.ogg`, пропускается) или ссылкой на
страницу документа `vk.ru/docX_Y`. Публичная страница документа содержит
`Docs.initDoc({... "docExt":"png", "docUrl":"https://psv4.vkuserphoto.ru/…"})`. Если
расширение — изображение, программа качает файл по `docUrl`. Личные документы без входа
отдают «Файл недоступен или удалён»; они попадают в `failed.csv` с причиной `doc_unavailable_or_private`.

## Проверки при скачивании

- Ограничение параллельности (`--concurrency`); к страницам vk.com не больше 2 запросов одновременно.
- Тайм-ауты: соединение 15 с, запрос `--timeout`.
- Повторы с экспоненциальной задержкой и случайным разбросом: сетевые ошибки, 408/424/429/5xx;
  для 429/503 учитывается `Retry-After`.
- 404/410 → `not_found`/`gone`; 403 → `forbidden`; редирект на `login.vk.*` → `requires_auth`.
  На реальном архиве проверено, что CDN VK примерно в 10–15% случаев отвечает 404/403
  на существующее фото, а через несколько секунд отдаёт его. Поэтому 404/403 повторяются
  с паузами 3, 6 и 9 с (`--soft-retries`), и только потом вложение считается недоступным.
  Без `--retry-failed` такие ссылки при повторных запусках не запрашиваются.
- Статус «скачано» никогда не перезаписывается последующей ошибкой.
- Содержимое проверяется по сигнатуре (JPEG/PNG/GIF/WEBP/BMP/TIFF/HEIC/AVIF). HTML-страницы,
  пустые и обрезанные ответы (размер не равен `Content-Length`) не сохраняются.
- Запись: поток → `.tmp/*.part` → `os.replace` в итоговый путь.
- Запросы идут без cookies и токенов. Авторизация и CAPTCHA не обходятся.

## Известные ограничения

1. **Пересланные сообщения.** В архиве есть только строка «N прикреплённых сообщений»,
   содержимого (и фото) нет ни в одном из 850 707 сообщений архива. Восстановить их по архиву
   нельзя. Каждое такое сообщение попадает в `skipped.csv` (`forwarded`).
2. **Записи на стене** в сообщениях выгружены без ссылки и без вложений → `skipped.csv` (`wall_post`).
3. **Разрешение.** Ссылки `impg` подписаны (`sign=`): любое изменение `size`/`quality`
   даёт 403. Поэтому сохраняется ровно тот размер, который указан в архиве. Обычно это
   самый большой размер, который VK отдал при выгрузке.
4. **Удалённые фото.** У заметной части старых фото CDN отвечает 404 или 403 (фото удалено
   или хранилище выведено из работы). Это окончательный ответ сервера, а не сбой программы.
5. **Ссылки-страницы** (`vk.ru/im?...z=photo…`) без входа ведут на `login.vk.ru`. Публичного
   изображения на них нет (проверено и на `m.vk.ru`). Альтернатива: в отчётах есть
   колонка `vk_ref` (`photo100000001_456239096`). При появлении доступа к VK API эти фото
   можно запросить методом `photos.getById` со своим токеном.
6. Фото в документах из личных «Документов» без входа недоступны (см. выше).
7. Время сообщений указано так, как его записал VK в архиве (часовой пояс аккаунта).
   Фильтр работает по этой дате.

## Тесты

```powershell
python -m pytest -q tests
```

- `tests/test_parser.py`: разбор страниц в формате архива: несколько фото в сообщении, «Вы»,
  удалённые пользователи, сообщества, `(ред.)`, пересланные сообщения, документы и голосовые,
  кодировки cp1251 и UTF-8, битые сообщения, совпадение быстрого предфильтра с полным разбором.
- `tests/test_date_filter.py`: русские краткие и полные названия месяцев, английский формат,
  `31 дек 2016 в 23:59:59` входит в период, `1 янв 2017 в 0:00:00` — нет.
- `tests/test_downloader.py`: локальный HTTP-сервер. Проверяются 404/403/429/500/503,
  HTML под видом JPEG, редирект на логин, публичный/приватный/PDF-документ, дедупликация,
  возобновление и повторный запуск CLI без лишних загрузок и копий.

## Структура кода

```text
main.py                  CLI
gui.py                   окно (Tkinter); собирается в exe через build_exe.bat
vk_export/
  runner.py              полный цикл «анализ → скачивание → отчёты», общий для CLI и окна
  lock.py                блокировка папки вывода от параллельных запусков
  archive_reader.py      ZIP или папка; список страниц; id владельца из метатега
  dates.py               разбор русских/английских дат, фильтр по периоду
  parser.py              разбор HTML (lxml), быстрый предфильтр дат, классификация вложений
  scanner.py             архив → вложения за период → progress.db (страница за страницей)
  storage.py             SQLite, безопасные имена папок
  downloader.py          асинхронная загрузка (aiohttp), повторы, проверка, раскладка, дедупликация
  reports.py             summary.json и CSV, вывод в консоль
  models.py              типы данных
tests/
```

Память: страницы читаются и разбираются по одной. Страницы, где по быстрому regex-предфильтру
нет сообщений из периода, полностью не разбираются. Полный анализ архива на 17 363 страницы
занимает около 12 секунд.
